## §2 · S0 — EVERY WAY A WRITER COULD OPEN AN EXISTING PAGE

**Pages could be opened. That is the finding, and it is why the report is right
anyway.**

| path | opens a page? | the catch |
|---|---|---|
| Journal panel → **Recent** | **opens** | **capped at 5**, Journal pages only |
| Journal **survey** | **opens** | Journal pages only (`inJournalView`) |
| **Drawers** panel tiles | **opens** | binder docs, plus loose docs via the Shelf law |
| a board card, **double-click** | **opens** | only pages already pinned on *that* board |
| **Boards connected** (PW1) | opens **boards**, not pages | — |
| **Page hand's list** ("Place page on board") | **places only** | the four faults below |

Every path that *does* open a page is named for **where a page lives** — the
Journal, a Drawer, a board — and **none lists all of a writer's pages.**

**THE OLD LIST'S FOUR FAULTS — a relabel would have fixed only the first:**

1. **Clicking a row PLACED the page** instead of opening it.
2. **It existed only on a board.** On a page surface there was no list at all.
3. **It could not see the pages writers make most.** It read `getJournalPages()`,
   and `inJournalView` is **false for every `origin: 'loose'` page** — exactly what
   **New Page** and the **Desk** create. **This is the one that matters most: the
   writer's newest page was invisible.**
4. **It capped at 30 before it sorted**, so A–Z ordered thirty pages and the rest
   were unreachable by any sort.

## §3 · WHAT SHIPS

**Clicking a row OPENS the page** (`flushNow`, then `routeForEntry`). **Placing on
a board is the row's secondary act**, behind its `⋯`, present **only where there
is a board to place onto**.

**THE RE-SCOPE:**

- **The section is OPEN PAGES**, and the writer-facing term for a document is
  **Pages** in every lexicon touch here.
- **Three rows visible, scrolling through the rest** — a viewport, not a cap.
- **Recency is by EDIT, not birth.** "Last created **or edited**". The old list
  ordered by `createdAt` alone, so a page written last year and revised this
  morning sat below one created after it and never touched again.
- **Starred pages sort first**, under every sort. A star is the writer saying
  "this one"; an ordering that ignored it would make them say it twice.
- **One derivation for the row:** `itemTitle`, the Journal lists' own, so a page is
  called the same thing everywhere it is listed. The home label now tells
  **Journal** from **Loose**, because the widened population mixes them.

### The judgments, flagged for Nick

1. **"The last three pages" is built as a VIEWPORT, not a cap.** A population of
   three would put the fourth page out of reach — **S0's fault 4 in miniature** —
   and "sortable by tag, board or drawer" says nothing over three items. The
   frame shows three rows and a scrollbar, so it can be judged by eye. **If he
   meant literally three, it is one line.**
2. **The list is on EVERY surface, not only boards.** A way to open a page that
   exists only while standing on a board is not the way.
3. **Boards are excluded** from it: they have their own doors and can never be
   placed on a board, so neither act applies. **One line if he wants them.**
4. **The menu's ORDER is not mine.** Nick fixed it — Current Page, Add to Board,
   Add Tag(s), Open Pages, Page Settings, New Page — and **PLAN DESK designs that
   menu**. This section does not reorder the hand around itself; it moves into
   place when their build lands. `b165` is the **Plan** menu; no Page-menu brief
   exists at this tree.

## §4 · HOW IT WAS CHECKED — INCLUDING WHAT THE CHECKS MISSED

**RED BEFORE: 12/14 on the old code** — but that alone did not prove what it
appeared to. On the old code the list is **absent** from a page surface, so the
population and cap checks failed *because there was no list*. And one check —
**"placing does not navigate" — passed with nothing placed at all.** Both were
rebuilt so each check can only fail for its own reason.

**ONE MUTATION PER FAULT, against the committed code:**

| mutation | what failed |
|---|---|
| **F4** cap before sort | exactly **FAULT 4 + the A–Z check** |
| **F1** click places | exactly the **two "click opens" checks** |
| **F3** population | **FAULT 3 — and not FAULT 4** (the cap check is scoped to Journal pages, so the population fault cannot fail it) |
| **F2** board-only | FAULT 2 and every page-surface check — it removes the surface they read |

**THE SITTING CAUGHT WHAT ALL FOURTEEN CHECKS MISSED.** On the board, the last
row's `⋯` lit up as expanded and **no menu appeared**: it hung below the row and
the list's `overflow-y:auto` clipped it from view. Every check passed through it,
because the harness's click **scrolls its target into view first** — precisely the
move a writer would not know to make.

- Fixed, and turned into **S4**, which reads the menu's geometry **without
  scrolling to it**, on the last row with the list scrolled to its end.
- **S4 then caught my own second cut:** centring the menu left a **3px overhang**
  (`menuBottom 501` against `listBottom 498`). I would have called that fine by
  eye. The menu is now **pinned to the row's top and bottom**, so its height
  derives from the row's. **S4 fails on both earlier versions.**

**A PRODUCT BEHAVIOUR THE HARNESS MEASURED, worth recording beyond this ticket:**
after typing, the cascade rail keeps **`opacity: 1`** but takes
**`pointer-events: none`**, and `document.elementFromPoint` at the strip's centre
returns the page stage. **The chrome looks present while being inert to the
pointer.** A page-side `.click()` sails through and hides it; a real pointer
cannot. The driver now **moves the mouse first** — what a writer does, and what
restores the chrome.

**AND `updatedAt` IS DELIBERATELY NOT SEEDABLE** — `persistence.ts` says the seam
"does not get a private clock the product does not have", and notes that nothing
in the ordering reads it. **This ticket now does.** So the recency check drives a
**real edit** rather than a seeded stamp, which is the better test anyway.
