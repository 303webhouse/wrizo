## §1 · THE DEFECT, AND WHY IT HID

The runner calls a file FAIL when one of its verdict lines contains `FAIL`, or
its exit is non-zero, and a file's exit reads its **live** checks. So a parked
check reaches the suite **only** through the file's `PARKED` verdict line. A
file whose `PARKED` line is a literal saying PASS has parked checks that can
fail and a verdict that cannot report it. The file is **structurally green**.

`item87.mjs` was that file. Its line read, verbatim:

```
ITEM87 PARKED: PASS (0 checks) — HARNESS_PARKED=1 armed; item 87 parks nothing: …
The empty list is the evidence, not an omission.
```

That was **true when written**. The 2026-08-17 amendment then pushed four parked
records and left the line alone. For a month it said **0** while **4** ran, and
said PASS whatever they returned.

## §2 · THE RATIFIED DESIGN, MEASURED — AND WHY THE GUARD READS SOURCE

The ratified comparison was "each file's printed `PASS (N checks)` against the
length of the list the file prints". Measured on 141's real parked leg, **output
alone cannot identify that list**:

| method | result | why it fails |
|---|---|---|
| by **name** (entries called `PARKED …`) | 68 / 70 | false alarm on `bm1`, whose second park is named `BM1 A4 sweep: …` |
| by **position** (last array before the verdict) | 57 / 70 | files that park nothing print no list, so the last array is their **live** checks |

A **static count of calls** is wrong for a different measured reason:

| file | call sites | parked checks run | why |
|---|---|---|---|
| `fx7` | 1 | 3 | a loop |
| `tu2` | 5 | 10 | helpers |
| `item9192` | 0 | 1 | pushed another way |
| `cd2` | 13 | 10 | three `PARKED-DRIVER` probes on failure branches (§4) |

So the guard **never compares numbers.** It reads each file's source and asserts
the verdict is **derived** from the array the file pushes into, which makes the
count right by construction.

Every file lands in exactly one class:

| lawful | defect |
|---|---|
| **DERIVED** — pushes; verdict reads that array's `.length` and has a FAIL form | **CANNOT-FAIL** — pushes; no path prints `PARKED: FAIL` *(item87)* |
| **DECLARED-EMPTY** — pushes nothing; prints a `PARKED` line anyway | **LITERAL-COUNT** — pushes; the count isn't the array's length |
| **SILENT** — pushes nothing; prints no `PARKED` line | **OTHER-ARRAY** — pushes; the line counts some other array |
| | **PARKS-SILENTLY** — pushes, prints no `PARKED` line |

Parks are detected by **declaration and push**, never by the shape of a helper.
A helper-shaped detector missed `item9192`.

**Validated against runtime ground truth** from 141's parked leg: `item9192`,
`fx7`, `tu2`, `cd2` and `bm1` classify DERIVED; five DECLARED-EMPTY samples
(`b3`, `m4`, `fx17`, `item121`, `item126`) each ran **0**.

## §3 · SCOPE (2) — ITEM87, AND WHAT THE FIX DOES NOT DO

**The line is derived now, with a FAIL form**, and the old literal is quoted
verbatim beside it. The header paragraph saying "the park list [is] empty" is
kept as written, with a dated note that it no longer is.

**The four records are byte-frozen and untouched** (zero `pok('PARKED` lines
changed). This needs saying plainly: **all four pass a constant `true`**, by
design. Their successor is the New Page chooser, which is unbuilt, and they are
"named rather than invented". So the line can now **report** a failure, and it
will say **PASS (4)** until those records have something real to measure. The
scope asked for four parks counted and able to fail. The count is fixed; the
*line* can fail; the *records* cannot, and inventing a condition for them would
break the rule that protects them.

## §4 · SCOPE (3) — CD2 EXPLAINED, NOT FLAGGED

`cd2` has 13 call sites and runs 10. The three that don't run are
`PARKED-DRIVER` probes, each on the **failure branch** of an existence check:

```js
if (!menuBtnThere) {
  pok('PARKED-DRIVER: a board row ⋯ is present to open', false, 'absent');
} else { … }
```

When every element is present, none of the three is reached: 13 − 3 = 10
exactly. They aren't unreachable; they fire when something is missing and record
it as a failure. This is the "never assume a node exists" rule working as
intended, and it's why a static count can't be the comparison: `cd2`'s count
legitimately changes with the page.

## §5 · SCOPE (4) — SILENCE, DECIDED

**Silence is lawful only where there is nothing to print, and the guard now says
which.** SILENT (no line, no pushes) and DECLARED-EMPTY (a line, no pushes) are
**reported as separate named lists** in the check's own detail, so a file that
prints nothing and a file with nothing to print never look alike. A file that
pushes and prints no line is **PARKS-SILENTLY**, a defect. Today there are
**none**.

**The protection this gives the DECLARED-EMPTY files is the point.** Many carry a
literal always-PASS line, which is exactly what item87 was before its amendment.
Each is one amendment away from being item87, and the rule catches that
amendment the moment it lands (mutation M4, §6).

*(No count of those files is written in the guard. My first draft said "the 21",
measured on one tree, and the next tree had 29. A number in a comment goes stale
without anything failing; the live count is in the check's detail, measured every
run.)*

## §6 · PROOF

**`item147` — 13/13, browserless:** population + silence + coverage + 10
falsifications and controls (item87's shape; an honest count with no FAIL form;
parks with no line; declared-empty; silent; a loop; a push that exists only in a
comment; a line reading the wrong array; a `PARKED-DRIVER` failure branch; a
derived control).

**Four mutations, each with its landing checked before its result was trusted,
all on committed work:**

| | mutation | result |
|---|---|---|
| M1 | restore item87's literal line | red — `CANNOT-FAIL: [item87.mjs]` |
| M2 | strip `bm1`'s FAIL arm | red — `CANNOT-FAIL: [bm1.mjs]` |
| M3 | blind the classifier to every push | red, 8/13, **coverage included** |
| M4 | give `item135` a park, keep its literal line | red — `CANNOT-FAIL: [item135.mjs]` |

M3 matters most. Item 141's guard once passed while scanning nothing. This guard
cannot: a classifier that sees no pushes finds no DERIVED files, and the
coverage check requires more than twenty.

**Two lessons from the mutations themselves:**
- **M3's first attempt never applied.** A `sed` pattern didn't survive the shell,
  and the "test" passed having tested nothing. The landing check caught it.
- **M4's first run stranded a mutated file.** My script's landing check was
  wrong: the replacement contained its own anchor. It threw after writing and
  before restoring. Restoring now happens in a `finally`, and the landing is
  checked against the exact intended text.

**A side effect caught and removed.** The first version's fixtures called their
helper `pok`, and the existing parked-records audit read them as **seven false
`NO_KEY` records**. The fixture helper is now `park` (the classifier detects
pushes, not helper names), and the audit's `NO_KEY` list is back to exactly
main's four.
