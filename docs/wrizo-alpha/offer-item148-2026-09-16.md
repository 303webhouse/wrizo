## §2 · THE GUARD, INVERTED

**Every `window.wrizo*` seam in `src/`, in every attachment form, is in scope.**
Each is either **durable** or a **named exemption with a written reason**, and
**every exemption's claim is checked**:

| class | rule |
|---|---|
| **durable** (14) | routes through `durable()` or `durableSeam()` |
| **the flush** (1) | `wrizoFlushNow`: it *is* the flush |
| **namespace** (2) | every member listed as a writer or a reader; writers wrapped; readers reach no writer and no storage |
| **sync-write** (6) | writes a key of its own module with `localStorage.setItem`, immediately; must reach **no** debounced writer, and must actually write something |
| **in-memory** (2) | reaches no writer and no storage |
| **read-only** (16) | reaches no writer and no storage |

**New seams, new namespace members, stale entries and placeholder reasons all
fail.** A read-only exemption is a claim, and the claim is checked: if it reaches a
debounced writer, it isn't true.

**"Debounced writer" is derived, never listed.** It is any `persistence.ts`
function that reaches `scheduleFlush()`, computed to a fixpoint from the app's own
source, as `KEYS` already is. A hand-maintained list of writer names would just be
a verb list under another name. `flushNow` writes immediately, so it is excluded
by construction.

**The trace follows imports across modules**, so a read-only seam can't hand its
write to a helper file and hide it there.

## §3 · THE INSTRUMENT WAS WRONG TWICE, AND HAD A HOLE

Each was caught by reading the red rather than obeying it.

1. **It accused the read-only `wrizoNotebook` of writing.** Two defects combined.
   It seeded from **every** identifier, so the property access `p.orderIndex`
   became a name to follow. And it took a **nested** `const orderIndex =
   notebookIndexAfter(…)` inside another function for a module definition.
   `notebookKey`/`sortNotebook` were then confirmed pure (`pageOrder.ts`: zero
   writes, imports only a type). **Fix:** seeds are free calls and member values;
   definitions are top-level only.
2. **Fixing that made every sync-write seam read as "writes nothing".**
   `{ get: getTheme, set: setTheme }` contains no call at all. **Fix:** an object
   seeds from its members' own expressions.
3. **A hole, not just a false alarm.** The first trace stopped at the seam's own
   file, so a read seam could launder a write through a helper module. **Fix:**
   the trace follows imports, with a falsification for exactly that.

> **A GUARD THAT FIRES IS CHECKED, NOT OBEYED** — here it fired wrongly twice, in
> opposite directions, before it fired correctly.
