## §3 · THE DEFECT, AND THAT IT WAS MINE

The open-blank branch was **dead code**:

```
boardName(getJournalEntry(id)?.text, 'Untitled') === 'Untitled board' ? '' : …
```

It derived the name with the crumb's own fallback (`'Untitled'`) and compared the
result against `'Untitled board'` — **two strings that were the same string** when
`boardName()` returned one stand-in for every caller. The moment the fallback
became a caller's parameter the comparison could never be true again, and a
writer naming a board for the first time **found the stand-in word sitting in the
field**, to be selected and deleted before they could type their own name.

**THE CAUSE IS MY OWN CORRECTION'S RESIDUE.** Parameterising the fallback was
right — the crumb has always displayed plain `'Untitled'`, and the headful sitting
captured it doing so. But changing a function's contract means finding every
literal that depended on the old one, and this dependent was **a string
comparison, not a call site.** My sweep found the call sites. **A contract change
sweeps dependents, not call sites.**

**THE SENTINEL IS GONE RATHER THAN CORRECTED.** Repairing the literal would leave
a magic string that must be kept in step with a fallback it cannot see — which is
exactly the drift that produced this, and item 136 retires those stand-ins
shortly. Deriving with `''` makes namelessness produce emptiness directly:
nothing to compare, nothing to keep in step.
