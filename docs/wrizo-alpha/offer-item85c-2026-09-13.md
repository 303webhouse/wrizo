## §2 · THE MIGRATION'S LAW (ratified; every file obeys it)

1. **`origin` and `source` are carried EXPLICITLY** — `null` where the row
   genuinely has no such field, the row's own value where it has one. The seam
   defaults `origin` to `'journal'` and hardcodes `source: 'page'`, so silence is
   a REWRITE, not a migration: absent `source` is what makes a row a raw capture
   (`computeFragmentItems` filters `e.source !== 'page'`), and absent `origin` is
   the pre-AB3 grandfather shape.
2. **`source: 'page'` is dropped** — the seam sets exactly that.
3. **`updatedAt` is dropped when textually equal to `createdAt`** — likewise.

Nothing else about any row changes. A field is carried as it is; **null is the
fact of absence, never a default.**

**IDS ARE RETURNED, NEVER SUPPLIED.** `createProject`/`createStoryPlan`/
`createDrawer` generate their own ids; overriding that would mean changing the
store's creators rather than the door. Fixtures adopt the returned id — locally
where it never leaves its block, and threaded through where it does (`fx9`'s
`seedFixture` and `j6`'s `seedFromDesk` now return their values, because `window`
state does not survive the reload in between).

## §6 · THE PRODUCT-CODE SURFACE (seams only, as authorised)

`persistence.ts` only. `createJournalPage` gains eight seed fields (`script`,
`starred`, `tags`, `deletedAt`, `shelved`, `orderIndex`, `updatedAt`, and `null`
handling for `origin`/`source`). Ten `window.wrizo*` seams, each a thin wrapper
over a store path that already exists and is already exercised by product code:
`PatchEntry`, `CreateProject`, `CreateBinder`, `PatchProject`, `CreateStoryPlan`,
`SetCurrentBeat`, `SetBeatStatus`, `CreateDrawer`, `SetProjectDrawer`, `FlushNow`.

**Zero schema. Zero user-facing behaviour change.** Product code calls the store
functions **directly** and never reaches `window`; the guard asserts that every
mutating seam routes through `durableSeam`/`durable`, so the app keeps its own
debounced cadence while the seams are durable for fixtures.

**Two constraint-(2) moments, both resolved without widening the house:**
`Project['type']` has three members but `createProject` accepts two, so the seam
mirrors the creator rather than the type (measured: all 19 project rows are
`'creative'`); and `m1` needed a later current beat and a completed beat, both of
which the store already had paths for (`setCurrentBeat`, `setBeatStatus`).
