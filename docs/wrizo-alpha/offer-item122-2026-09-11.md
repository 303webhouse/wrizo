## §2 · WHAT WAS BUILT (Nick's ruling, four pieces)

**1 · DRAFT'S MARKERS COLLAPSE.** B/I/U render the STYLE, not the syntax. The
**default** register in `decorateEditorFor` moves to reveal-adjacent rather than
each Draft call site passing an override — a default cannot be forgotten at a
fifth site, and sites that disagreed would flicker between registers as the
writer types. `BoardCardPopup` already passed it explicitly, so page and card
share one register.

Both hazards were settled by measurement, not argument:
- **data loss** — `font-size:0` marks survive `el.innerText`; `display:none` and
  `visibility:hidden` were run as **controls** and both stripped the markers;
- **the caret** — typing `X` at offset 2 inside a collapsed bold run produced
  `a **boXld** b`, exact; the row persisted byte-exact.

**NAMED LIMITATION:** reveal fires on the next **keystroke**, not on caret move
alone, because `redecorate` runs from `onInput`. That is the card's own shipped
behaviour inherited faithfully. Closing it is ratified as the **next window's
first job** (a `selectionchange`-driven redecorate on **both** surfaces).

**2 · STRIKETHROUGH.** `~~` joins the frozen set — a single tilde carries no role
in prose, so it needs no defence the way a single underscore did. A case in
**both** inline passes, `.md-strike`, a lexicon string, and a button seated
**after** underline so the row reads **B I U S**: the new control does not
displace a position the writer's hand has learned. **`strike.mjs`, 7 checks.**
**`ab2` generation-5 park**, gen-4 quoted byte-for-byte inside it, roster twelve
→ thirteen.

**3 · `::selection` IS BRASS.** There was **no selection rule at all** before
this. Painted from `--brass` with the paired `--on-brass` foreground that already
existed for exactly this job, so selected text stays legible instead of
inheriting whatever ink it had. Both `::selection` and `::-moz-selection`.

**4 · DRAFT'S ACTIVE STATE — BUILT, NOT UNSTUCK.** Draft's rail had **no active
state at all**; the stuck highlight Nick saw lives on Free Write, whose styling
item 121 removes. So this builds one caret-derived from the start. It needed no
new prop: `editorRef` is already the editor's host div and `getCaretOffset` is
the shared reader, so a pure `marksAt(text, caret)` plus one listener does it.

Two judgments, both ratified:
- **"Active" = the caret anywhere WITHIN a run, markers included** — deliberately
  the same boundary reveal-adjacent uses to un-collapse the marks. Two rules
  disagreeing about "inside" would be worse than either alone.
- **`selectionchange`, never `keyup`** — the only event that fires for every way
  a caret moves, including the formatter's own programmatic ones. Reintroducing
  the stuck highlight while fixing it would have been a poor joke.

**5 · THE DEAD RENDERER IS DELETED** (ratified): `decorateMarkdown` and
`decorateInline` are gone. Precondition checked first as ruled — **no caller
anywhere**; every other mention was comment prose.

## §3 · A RED OCCURRED, AND IT WAS MINE

**The first pair came back 76/77 in BOTH legs**, on `item83f.mjs`'s E3 check:
`{"marks":[],"textLength":23}` — **zero `.md-mark` elements**.

**Cause: my own change.** `decorateMarkdown` wrapped `LEADING_TABS` in
`.md-mark`; `decorateMarkdownForCard` had **no indent handling at all**. Moving
the default register silently dropped Draft's indent marker. My commit had
claimed page and card "now genuinely share one register" — **the two passes were
not feature-equivalent, and I asserted equivalence instead of checking it.**
Review did not catch that. The suite did.

**The port carries the decision that matters more than the fix: the indent mark
DELIBERATELY DOES NOT COLLAPSE.** `**` is syntax standing in for an effect the
reader sees elsewhere, so hiding it loses nothing. A leading **tab IS the
effect** — it has no ink of its own, and the indentation the writer sees *is*
those characters. Collapsing it via `font-size:0` would render the tab
zero-width and silently un-indent the paragraph: a missing marker traded for a
**deleted layout**. Getting that backwards would have been worse than the bug.

## §4 · A SECOND RED, NOT MINE — AND ITS MECHANISM

The next pair came back **78/79 unparked** on `bg2.mjs`'s lane-law check,
reporting `pressColour: rgb(233, 138, 0)`.

**That is not a wrong colour. It is an INTERMEDIATE one** — literally between
brass `rgb(255,152,0)` and brass-press `rgb(232,137,0)`, one step short of
arriving. The three states are reached through a CSS transition and were sampled
after **fixed sleeps** (250ms hover, 150ms press); under suite load the read
lands mid-transition. It then passed **4 of 4 standalone**, which is exactly how
a timing dependency disguises itself as a flake.

**Not caused by item 122:** `--brass-press` is `#e88900` and untouched here.

**THE CURE POLLS FOR STABILITY, NEVER FOR THE EXPECTED VALUE.** Polling until the
colour equals what the assertion wants would make the check pass **by
construction** — green even with the lane law broken. Waiting for two agreeing
reads measures the settled state and leaves the verdict to the comparison.

**FALSIFIED, not asserted:** perturbing `--brass-press` to `#d07700` made it
**fail 1/23**; restoring returned it to **23 PASS**. The settle did not neuter
the check.

**A PROCESS CORRECTION ON THE RECORD:** I first re-ran the unparked leg *without*
the fix. That is a **re-roll** — a run with no repair in it can only shop for a
green — and it was stopped on Fable's correction. The stamp above names the tree

## §5 · THE POLL CENSUS — 1, NOT 25

Chartered to find every check whose poll condition **is** its assertion. Measured
over the **full enumeration, 79 files**, 920 `waitFor` sites and 1 `settle` site:

| class | count | standing |
|---|---|---|
| poll the sampled **value**, assert it against a literal | **1** (`bg2` S1) | **fixed above** |
| poll a condition on a deadline that **fails**, then assert | **1** (`bm1` S2) | correct as written |
| `waitFor(EXPR)` then asserting the same EXPR in scope | **0** | confirmed two ways |

`bm1`'s is the legitimate form: if the shelf never includes the board, `settle`
returns `false` and the assertion **fails**. Item 129 is the proof — that settle
never rescued the absent row, which is why the bug was findable.

**MY FIRST CENSUS SAID 25, AND IT WAS WRONG.** It paired *any* `waitFor`
expression with *any* later `ok()` containing that string anywhere in the file —
unscoped, and without requiring the expressions to match. Spot-checking two hits
killed it: `ab1` waits on `.script-sheet` and asserts `.desk-frame`; `w2` waits on
`.board-canvas` and asserts `.desk-rail-wayback`.

**That is the same failure this window had just diagnosed in `bg2`, committed by
me one level up: an instrument returning a confident number that describes
itself rather than the world.** The rewrite added scope and identity, and an
independent second method (set intersection rather than forward-walking) agreed
at 1. **Had 25 been reported, the outcome would have been a ticket chartering a
13-file sweep against a population that does not exist.**
