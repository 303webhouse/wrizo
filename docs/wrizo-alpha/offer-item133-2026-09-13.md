## §3 · WHAT WAS BUILT

**BOARD — the rename.** `board.text` is a pure label, so writing it **is** the
rename. The name in the board's own crumb edits in place: **Enter or blur
commits, Escape reverts, empty reverts to the previous name**, committed through
`patchJournalEntry` — the same path every other edit uses, so there is no
naming-specific pipe.

**PAGE (A) — discoverability.** J10's model stands. Reaching the displayed name
focuses the editor and lands the caret at the **END of the first line**: where a
rename is typed, not at character zero where the first keystroke would shove the
name rightwards. **No help text** — the gesture demonstrates the relationship by
using it; a tooltip would be the same fact told rather than shown.

**THE GESTURE IS OPTIONAL ON THE SUBJECT.** `PageFace` also renders for pages
that are not the one open in the editor, where there is no caret to place —
those keep rendering the name as plain text. **A control that cannot act teaches
the writer the wrong thing**: item 118's unlink lesson, applied before it could
repeat.

## §4 · THE DRIFT IS THE TICKET'S REAL FINDING

The same board name was derived **three different ways**:

| site | derivation | fallback |
|---|---|---|
| `BoardEditor` | whole trimmed text, **uncapped** | `'Untitled'` |
| `Cascade` | `firstLine(...).slice(0, 60)` | `'Untitled board'` |
| `CascadePanels` | split the newline, own 60-cap | `'Untitled board'` |

Three readings of one field, disagreeing about **truncation AND about what an
unnamed board is called** — so **a board could answer to two names on two
surfaces**. Invisible only because nothing could rename one; the instant a
writer renames a board and watches the label, it shows.

`boardName()` in `entryText.ts` is now the one source at the sites this ticket
touches. **The 30-site sweep is its own ticket.**

**AND THE FALLBACK IS THE CALLER'S, after a correction.** My first cut returned
`'Untitled board'` uniformly — which **silently changed what the board's own
crumb displays**; that surface has always said plain `'Untitled'`, and the
sitting captured it doing so. Item 136 retires these strings wholesale under the
stand-in rule, and changing one here would have left **two half-rules on one
tree**. So `boardName(text, fallback)` single-sources **which characters the
name is**, and nothing else. **The ratification licensed the derivation, not the
words.**

## §5 · TWO DEFECTS OF MINE, BOTH CAUGHT BY INSTRUMENTS

**1 · THE CARET LANDED AT THE END OF THE PAGE.** `el.focus()` lets
`ForwardOnlyEditor` run its own caret placement, which collapses to the
container's end — and that lands **after** a synchronous `setCaretOffset`,
silently overwriting it. **Measured: offset 35 on a 16-character first line.**
The feature would have shipped *looking* correct — the name **is** reachable,
the editor **does** focus — while depositing the writer at the bottom of their
page. Placed in a `requestAnimationFrame`, the caret stays put.

This is the window's own law violated in my own product code: I had applied
*measure the settled state* to **reading** all week, then wrote a caret into a
surface still arranging itself.

**2 · A HOOKS-ORDER VIOLATION — item 104's class, reintroduced.** The stamped
pair came back **78/80 in BOTH legs**: `hooks-order.mjs` and `hooks-order-ast.mjs`
both reporting `useState` at `:1822`/`:1823` **below the early return at
`:1753`**. `if (!initialEntry) return null` sits between. On a render where the
board's row is missing — **a board deleted on another device, its tombstone
arriving on a sync pull, which is reachable and is the exact scenario item 104
was opened for** — those hooks would not run, React would see fewer hooks than
the previous render, and **#300 would blank the whole tree**.

The cause is mundane: I wrote the state **beside the `title` derivation it
serves**, because that reads better. It does. **State belongs with the HOOKS,
not with the feature it describes** — proximity to its own feature is the pull
that puts it in the wrong place. The note now sits beside the code.

**Both guards fired, the line-scanner and its AST successor** — cheap
confirmation the finding was real and not a parser artifact. The guard is static
and browserless: about **one second** inside a suite of 80, and it named the
file, component, hook, line, and the early return it sat below.
