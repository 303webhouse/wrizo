## §1 · THE RULE

> **THE WAITFOR IS THE PROOF; NAVIGATION IS NOT.**

A harness that reads a `window.wrizo*` seam as its first probe after arriving on a
page is racing the app's own module init. A navigation is a **request**; a settle
is an **observation**. When the race is lost the seam is `undefined` and the file
dies with a TypeError inside whichever check happened to be first — reporting
nothing about the thing it was testing. `item97.mjs` paid this for a day, and its
own source records it.

> **ORDER IS THE RULE — A SETTLE BEFORE THE NAVIGATION PROVES NOTHING ABOUT THE
> DOCUMENT AFTER IT.**

Events are walked in **source order** through a two-state machine: a navigation
unsettles the document, a settle settles it, and a seam read while unsettled is
the violation. A guard that merely counted both tokens in a file would pass the
exact shape it exists to catch.

**A `sleep()` IS NOT A SETTLE,** and is rejected explicitly. A poll ends when the
condition holds; a sleep ends when the clock says so.

## §5 · THREE DEFECTS IN MY OWN SCANNER, AND ONE GREEN THAT MEANT NOTHING

Each was caught by checking the instrument's output rather than trusting it.

1. **It flagged `seed-guard.mjs`'s synthetic fixture strings** — a browserless
   file with no `app`, which cannot race a page that does not exist. Only files
   that IMPORT `withHarness` are scanned now: a property, not a name exclusion,
   so the next browserless guard is covered without anyone remembering.
2. **It flagged `pw1.mjs`, which rolls its OWN settle** — a `while` loop
   re-evaluating until true, reached through a second helper. That is a settle by
   every property that matters. Helpers resolve to a **fixpoint** now.
   > **A GUARD THAT KNOWS ONLY THE HOUSE SPELLING TEACHES PEOPLE TO WORK AROUND
   > IT.**
3. **Its first fix tested for the WORD `withHarness` and flagged this very file**,
   whose prose and matcher both name it — the same fault it had just fixed, one
   level up. It tests for the **import** now.

**AND IT PASSED WHILE BLIND.** A mangled classifier — two literal backspace bytes
(0x08) written through a shell heredoc, invisible in `grep`, `sed` and every
listing — rejected every file, and the guard reported a clean `population: 0`
having scanned **nothing**. Only the coverage number in its own detail betrayed
it.

> **A SCAN OF ZERO FILES IS NOT A CLEAN RESULT — COVERAGE IS ITS OWN CHECK.**

Coverage is now a check of its own: a harness directory that yields no harnesses
is a broken classifier, not a clean tree.

**Mutation-tested, on committed work** — and the first attempt taught the same
lesson again: a `perl` substitution that never matched left the file untouched,
and the "mutation test" passed having tested nothing. Applied verifiably by line
number, the guard reds and names `j4`. Breaking the classifier reds the coverage
check.

> **A MUTATION THAT DOES NOT APPLY TESTS NOTHING — VERIFY THE MUTATION LANDED
> BEFORE BELIEVING THE RED.**
