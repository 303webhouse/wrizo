Mockup A — SCHEMA

The Flux Circuit is not a board on a desk. It is a region of cyberspace: an infinite schema where each card is a record (a node with an id, a type, a token count and a status), links are live traces with data packets running along them, and the ground is circuitry at every scale. You can zoom out past the circuit into its cartridge, rack and cache, and in past a node until the words dissolve into their code points.

The design team (two passes)

Convened: a sci-fi game UI designer (diegetic HUDs), a motion / VFX designer (glitch, signal), a data-visualisation architect (graphs, level of detail), with the house Experts (cognitive scientist, Deleuzean philosopher) and Architects (frontend, interaction).

Pass 1 — proposals. (1) A node graph on circuitry with semantic zoom. (2) Stacked 3D strata (see Mockup B). (3) A literal Matrix code-rain wall with cards inside it. (4) A "terminal" board where cards are lines of code in a file.

Pass 2 — critique and trim. The terminal board (4) loses spatial memory: the writer cannot find "the card top-right". Cut. The full code-rain wall (3) is ambient, not stimulating, and fights the text for attention; it is kept only as a substrate made of the writer's own words (Mockup B). The cognitive scientist set the motion budget: stimulation lives in the connectors and the zoom, the glitch stays under 3 Hz and damps while you drag, zoom or type (canon §6). The architect held the line that every view is a projection of the same card data: no new fields.

Recommendation. Build two contrasting directions: A (this file): a flat infinite schema — precise, readable, closest to today's interactions; B: strata — the spectacle direction, layers in depth.

Guiding concepts, as built here

  • Conceptual space over physical space — no surface, no edge, no weight. Position means relation; scale means level of abstraction (node → circuit → cartridge → rack → cache → unindexed).
  • Visual stimulation over ambient feeling — packets on every link, traces that carry current, Signal-Loss glitch events (tear lines, shear, macroblocks, backlight dips) on the ground, never on the text.
  • Language as code — each node shows its id, type and token count; zoom in far enough and every letter becomes a cell with its Unicode code point.
  • Humanity as a bug — every human-written node carries STATUS: UNRESOLVED // HUMAN; hover one and the system attempts an autocorrect, scrambles the text toward code, and is rejected. It is theatre: the stored words are never touched.

Familiar, not lost (the switch)

  • Every node sits at the card's own x / y, at the card's own size: the shape of your board is the shape of your circuit. Spatial memory survives the switch.
  • Orange is you: the last node you touched carries the thin orange bar, and Locate last node flies the camera to it from any zoom level.
  • Press Jack out: the same nodes become Arbor cards in place, camera unchanged. Press again to jack back in.
  • Views map one to one: Live = Open, Sequence = Storyboard (lanes by act, in reading order). Outline / Walk would follow.

What this mockup does not decide (would go to Fable)

  • Remembering the camera (zoom / position) per board would be a new saved field — not assumed here; the camera lives in memory only.
  • Building it means a Flux-only renderer for the board stage (level of detail, canvas layers): an architecture pass, not a cosmetic one.
  • The cartridge / rack / cache levels read today's real membership (board → project → drawer → shelf); sibling contents are drawn as placeholders here.
