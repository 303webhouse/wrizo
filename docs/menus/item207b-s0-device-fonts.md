## 1 · WHAT THE CODE ALREADY DOES (drift-checked at 5653417)
- **The stored shape is already reserved and already renders.** `StoredFace = { name, generic, source: 'device', … }` exists; `faceStack()` gives a face this build does not know **its own name first, then its generic class** (`'Some Family', Georgia, serif`), so **a device font needs no `@font-face`, no blob and no storage to RENDER — the browser resolves an installed family by name.** `pageSettings.face` already syncs (whole-blob jsonb). **Phase 2 therefore needs no schema, no server, no font bytes.**
- **What is genuinely new is only three things:** (1) *enumeration* — the writer must be able to SEE which families are installed (a name cannot be typed reliably); (2) a *class* for the family (serif / sans-serif / monospace) — Local Font Access returns names and styles, never a class; (3) *availability* — telling the writer, quietly, when a page names a family this device lacks.
- **The Electron main process installs NO permission handler** (`src/main.ts`, 45 lines: a bare `BrowserWindow`, `contextIsolation: true`, no `session` call). So the question the design left open — "Electron's permission handling for the API is UNMEASURED" — has a concrete shape: *what does Electron 31 do with a `local-fonts` request when no handler exists?*

## 2 · THE PLAN, AS DESIGNED (nothing built)
1. **The door:** "Add a font…" is the roster's LAST row — **full form only** (Draft and Revise), absent in Free Write and the card strip (his Q2). It drills in, in the drawer (166's R2: never a second panel), to a plain scrolling list of installed families, each set in its own face. **Absent, not greyed, wherever `queryLocalFonts` does not exist (Firefox, Safari)** — the door never offers what the browser cannot do.
2. **On the pick:** the permission is asked THEN, never on load (design check 8); the name is added to a per-device library `wrizo-device-fonts` (`localStorage`, `[{ name, generic }]` — the `wrizo-theme-prefs` precedent), and set on the page. **Free Write's roster lists the nine plus the library** — no add row. A refusal leaves the roster untouched and says so in one plain sentence.
3. **The class is MEASURED, not asked** (`store/fontDetect.ts`, written): monospace when `i` and `W` advance alike; serif when a capital `I` is much wider at its top than its middle; else sans-serif. Asking the writer for a class would be a second control in a menu his law keeps minimal. **Unmeasured until the probe: how right it is** (a display or script face is a judgement call and lands in sans-serif).
4. **Availability is measured** (`isFontAvailable`, written): a missing family falls through to the generic, so its width equals the bare generic's; an installed one does not. Used for the *"Substituted on this device"* mark — a quiet mark inside the control, never a toast — on `device` faces only (the two named faces have a metric-compatible fallback and never nag).
5. **Nothing enumerates fonts except the writer's own pick.** `fontDetect` asks about ONE name; the enumeration happens only inside the add drill-in, on a click. That is the fingerprinting boundary the design named.

## 3 · WHAT THE PROBES MEASURED (run 2026-09-30, grant `tools-207b-probes-20260930`)
**Web (`item207b-s0-probe.mjs`, real Chromium via CDP):** `queryLocalFonts` exists. **With no grant and no user gesture, it REJECTS** — `SecurityError: "User activation is required."` — confirming the design's "asked on the click, never on load" is not optional, it is the API's own contract. **With the grant: 483 faces, 208 unique families, 1650ms, fields `family/fullName/postscriptName/style` (+ a `blob()` reader never called)** — Arial and Times New Roman both present. **Cost of one row per family, each set in its own face: 659ms plain, 4ms with `content-visibility:auto`** — the design's jank worry was real and `content-visibility` (already built into `.wz-type-list--add .wz-type-row`) answers it completely, not partially.
**Classifier, against twelve known Windows families: TEN correct, TWO WRONG — Verdana and Tahoma both read as `serif` (expected `sans-serif`).** A real, measured defect in `classifyGeneric`'s ink-band heuristic (`fontDetect.ts`), not yet fixed — it needs re-verification in-box, so it is named here rather than patched blind. Every other family (Times New Roman, Georgia, Cambria, Palatino Linotype, Arial, Calibri, Segoe UI, Courier New, Consolas, Lucida Console) classified correctly.
**Electron (`probe-local-fonts-electron.cjs`, the real shipped 31.0.0 shell):** all three configurations (no handler / a handler that denies / a handler that allows) return **`asked: []`** — **Electron's `queryLocalFonts()` never routes through `setPermissionRequestHandler` at all.** It succeeds silently, no gesture required (`ms: 4-5`), same 483/208 count as the web probe, regardless of what any handler would have said. **`main.ts` needs NO change — it already works today, and there is no way to gate or deny it from the main process even if a future ticket wanted to.**
**A second real finding, from `item207b.mjs`'s own refusal check going red first:** a permission GRANTED then REVOKED mid-session (`Browser.setPermission … denied` after an earlier grant) does not make `queryLocalFonts()` reject — **it resolves successfully with ZERO entries.** `openAdd()` (`TypeControl.tsx`) assumed a rejection; fixed live (an `ok:true` empty result is now treated the same as a refusal — one honest sentence either way, since a genuinely fontless OS is not a real scenario worth rendering as silent nothing). Re-verified in-box: `item207b.mjs` 20/20 both legs after the fix.

## 4 · HANDED UP, WITH A LEAN
**Where does the device library live for a writer on two machines?** The design says per-device `localStorage` (a font is a property of the machine). **The cost, honestly:** a page dressed in Garamond Premier on the desktop opens on the laptop in a *serif fallback* and says "Substituted on this device"; the laptop's roster does not offer Garamond Premier (it was never added there). **That is correct and is what Fable ruled ("the name syncs; a device without the font falls back in its class")** — recorded so it is not mistaken for a defect. **The rival, in its strongest form:** sync the library's NAMES through `page_defaults`-style storage so every device's roster lists every font the writer ever added, with the missing ones marked — a writer then sees, on the laptop, which of their fonts they have not installed. **Its cost is a new synced key and a roster that lists fonts the device cannot render; the unmeasured risk sits on the lean** (nobody has watched a writer move between two machines with a device font). **Lean: per-device, as ruled; the rival is a separate item if he asks.**
