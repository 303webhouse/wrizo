## §2 · C8: HOW A RED BECAME A FINDING, NOT A TEST EDIT

C8 shoved a group past the sheet's edge. It came back with **`cAfter ===
cBefore` to the last digit** — not clamped, **not moved at all**. Its two clamp
clauses had passed only *because* nothing moved; the "and it still moved" clause
is what caught it.

**Not fixed by editing the test.** C6 (same fixture, small in-sheet drag)
passed, and C8's release landed at negative screen coordinates — so a CDP
artifact was a live explanation. Diagnosed with probes kept out of the tree:

| leg | capture | release reached sheet | result |
|---|---|---|---|
| release **inside the viewport**, just past the sheet edge | none | **no** | **move lost** |
| release off the viewport (C8's shape) | none | no | move lost |
| control — release inside the sheet | none | yes | kept |

**The first row rules out the instrument** — an ordinary in-viewport release.
**Product defect:** a trusted mouse drag after the arming double-click never
receives `gotpointercapture` (`setPointerCapture` returns and
`hasPointerCapture` reads true, but the capture is never applied), so a release
anywhere outside the sheet never reached `commit`. The move was lost, **and the
drag stayed live** to the next buttonless mouse movement. The product's own
`try { setPointerCapture } catch {}` is what hid it. Double-click timing ruled
out (60ms and 1500ms identical).

## §3 · THE FIX, AND THE PROOF THAT IT'S THE FIX

**The dependency is removed rather than explained.** The press stays on the
sheet; move, release and cancel are heard on **window**, because a gesture isn't
over until the writer lets go, anywhere. `setPointerCapture` stays best-effort,
no longer load-bearing. Every handler is guarded by the pointer that began the
gesture; window `blur` cancels an in-flight one; and **a cancel no longer
commits** — `pointercancel` had been wired to the move's `commit`, which would
have persisted a half-finished move the platform took away.

**Mutation-tested**, fix committed first: moving *only* the listeners back from
window to the sheet turns **exactly five checks red and no others** (37 stay
green) —

- C8 — the group doesn't move
- C8b — the in-viewport release is lost
- **C8b — the drag is left stuck** (inferred before; *measured* here)
- C14 ×2 — item 121's stroke is lost, and no out-of-sheet move is heard

One variable changed; only these five responded. Restored by `git checkout`, the
mutant bundle rebuilt over **before** the re-stamp, and the re-stamp's bundle
hash confirms it.
