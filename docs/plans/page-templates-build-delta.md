## The rebase onto typing-latency (Fable Oct 17)
The first S3+S4 built the lens as a string post-pass in `draftDecoration.ts` (`lensHtml`). `main`'s `lineRows.ts` now builds the page as one `.wz-row` per line and writes only the rows that changed, so that funnel no longer draws the page; the semantic conflict was bigger than the textual one. What changed, all of it routed through the rows:
- **No lens in `draftDecoration.ts` or in the editor's first-paint string** (`draftDecoration.ts` is byte-identical to main's; a pin says so). `ForwardOnlyEditor` carries only the lens PROPS, the key door and `data-template`, plus a `[lens]` effect that calls `refreshLens`.
- **The number is an attribute on the row ELEMENT, not markup inside it.** `lineRows` compares a row's `innerHTML` (the kept-row path) and keeps `written` html per row; an attribute inside the markup would make a typed letter's row look changed and rewrite the caret's row on every keystroke. The numbers also depend on the rows ABOVE, so they are re-derived over all rows after each write (an outline is short; it touches an attribute only where it differs, and does nothing on a page that is not an Outline).
- **The Outline's Tab / Enter result goes through `writeRows`** (decorateEditorFor only as the no-rows fallback), as the format press does.
- **drawers-p1 D1a:** main's own successor ("on a branch the diff is REPORTED, not judged") already covers a branch that changes the typing surface, so the page-templates D1a park was dropped in the rebase. Parks: **15** (was 16): `ab2` 2, `item211` 4, `item83f` 2, `item87` 2, `page-templates.mjs` 4, `drawers-p1` 1 (D2b).
- **The rows-shadow instrument, per lens.** `runtime-verify` arms `window.__wzVerifyRows` on every page; X7 (Outline) and X8 (Bibliography) now assert zero `WZ-ROWS-MISMATCH` with renders checked, across Tab / Shift+Tab / Enter / typing / undo (Outline) and an Enter plus a typed entry with an italic title (Bibliography). Written, unrun.
- The string-lens harness checks (L1 to L9 and their 4 mutants) retire with the string lens; in their place nine source pins on the row lens (R1 to R9) each run against seven mutants that must land and be killed.

## Where the build departs from the plan, or found something the plan did not (for review)
1. **Found in S0, closed before the key existed:** "Set as my default" copies the open page's settings into every future page (the item-114 trap). `store/pageDefaults.ts` `dressOnly` strips `template` as it strips `kind`; a mutant proves it.
2. **The item-158 Tab machine would have fought the Outline.** It indents the whole PARAGRAPH on a Tab tap (applied on release), and an outline is one unbroken paragraph. While an Outline is in Draft the machine stands aside (a ref read at press time, above the early return so the hooks guards hold), and the Outline's own Tab acts on the row. Not in the plan.
3. **The unborn slot now follows the address on one thing**: its template (`UnbornProvider` re-registers the slot when the descriptor's template changes), so the picker's brass and the lens read the choice before the page is born.
4. **Naming:** the structured editor's fields type is `TitleSheetFields`, because `types/index.ts` already has a `TitlePageFields` for the (dormant) screenplay title page.
5. **Revise draws the lens too** (Draft and Revise are the free-edit modes); Free Write's forward-only runway never does. The Outline's keys act in Draft only.
6. **Instrument changes (reads, not assertions):** the harness reads of the picker rows added beside the old reads.
