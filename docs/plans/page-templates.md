## 1. How each template is stored (no new column)

**The rule: the text is the truth; the template is a lens.** A page's `entry.text` always holds everything the writer typed, in the dialect above, readable as plain text. `pageSettings.template?: 'outline' | 'title' | 'bibliography'` (absent on every page that never chose, absent for Blank and for Screenplay) only switches which lens draws it and which keys act. Lose the marker (an old client, a merge) and the page is still a readable, editable Draft page; nothing is trapped behind it. No other field, no table, no migration.

| Template | In `entry.text` | Drawn as |
|---|---|---|
| **Outline** | One heading per line. **Level = leading tabs, 0 to 2** (three levels, as the mockup). No numbers stored. | Numbers (`1.`, `1.1`, `1.1.1`) derived from the levels, and a hanging layout |
| **Bibliography** | One entry per line (a soft-wrapped line is still one line). Titles as `*italic*`, which the dialect already supports. | A hanging indent on every row and a gap between entries |
| **Title Page** | Five fields in one fixed order, see below. | The standard manuscript sheet: contact top-left, word line top-right, title and author centred lower |
| **Screenplay** | Unchanged: `pageType: 'script'`, `script` jsonb, `text` = `serializeScriptDoc` shadow | `ScriptEditor` |

**Outline details.** Numbers are never stored, so reordering, indenting or a merge cannot leave a stale number. Rules (pure module `store/outlineText.ts`, golden-tested): a line's level is its leading-tab count clamped to 0..2 and to at most previous level + 1 (the mockup's Tab rule); `Tab` / `Shift+Tab` change the level through the existing `LINE_DIRECTIVE.indent` machinery (`rewriteLeads`), not a second mechanism; `Enter` opens a row at the same level; `Backspace` on an empty row removes it.

**Title Page canonical text** (pure module `store/titlePage.ts`, golden-string tested like `scriptText.ts`, which is the precedent for a structured document with a prose shadow):
```
<contact line 1>          left-aligned, 0..n lines (name, address, email)
<contact line n>
>> <word line>            the first right-aligned line (e.g. "About 62,000 words")

>< <TITLE>                centred block: title,
>< by                     the fixed word,
>< <Author>               and author
```
Parse is by structure (lines before the first `>> ` are contact; the first three `>< ` lines are title, "by", author), so it survives a merge of any one field. The title is stored as typed (the mockup's uppercase and letter-spacing are CSS, unlike script's stored uppercase). Empty trailing fields serialize to nothing, so a fresh Title Page has **no text and no words** until the writer types; "by" appears only once a title or author does. If the text does not parse (edited by hand in Draft, or an old client), the page simply draws as plain Draft text: the lens declines, nothing is lost.

### How it survives save, sync, export and copy
- **Save and sync.** `text` and `pageSettings` are two columns of one row, pushed in one upsert under the existing last-write-wins row merge, so they cannot skew apart. Leading tabs, `>> `, `>< ` and `*` are ordinary characters in `text`; nothing on the save path trims or rewrites them (to be proven by the round-trip check, below). `page_settings` is a whole-blob jsonb on the server, so an inner `template` key passes through untouched (the "server drops unknown fields" trap is for unknown top-level ENTRY fields, not keys inside a jsonb). **Old-client risk:** the current patch path spreads `pageSettings`, so an unknown `template` key rides through any edit that uses it; S0 greps every other writer of `pageSettings`, and a path that rebuilds it would drop `template` and leave the page a plain Draft page. Degradation is visible, never destructive.
- **Export** (`store/pageExport.ts`; today there are only `.md` and `.txt`, built by `pageBodyFormatted` / `pageBodyPlain`, the same two seams Copy uses). Both gain one template-aware branch each, beside the existing `script` and `board` branches:
  - Outline `.txt`: numbered, indented with **spaces**, e.g. `1. Arrival`, `  1.1 The late ferry`. `.md`: the same numbers, nested. **Not leading tabs in `.md`**: a tab-indented line in Markdown renders as a code block, and the default path (tabs kept in `.md`, stripped in `.txt`) would lose the levels in plain text or break them in Markdown. This is the one place the existing export behaviour is wrong for a template.
  - Bibliography: one entry per paragraph (blank line between) in both files; italics kept in `.md`, stripped in `.txt` by the existing reader.
  - Title Page: `.md` keeps the dialect tokens as it does for any page; `.txt` strips them as it does today (the alignment is layout and `.txt` has none), keeping every field in order.
- **Copy.** Copy My Words and Copy Formatted already call those same two bodies, so they inherit the export branch with no second implementation. A **selection** copy (the in-app-copy-format design, plan f2a9f956) carries lead tokens by its own rules, so an Outline selection keeps its tabs, and the derived numbers are never in the DOM text and so are never copied.
- **The typing path (the real risk).** Numbers and hanging indents are decoration on the live editor. The font-span/typing-latency collision (ledger 79) is the lesson: a row model that does not know a mark corrupts the shadow. So: numbers are drawn as `::before` content from a `data-` attribute (never text nodes), the hanging indent is CSS on the row, DOM `textContent` stays byte-equal to the stored text, and each lens gets a ROWS-SHADOW check. **Sequence the build after `typing-latency` and `typed-literal` merge.**

## 2. The new-page path and the Back note
- **Rule (unchanged from Screenplay, now for every template):** picking a template on a page that is **empty** (no words, no ink, no script content) applies **in place**: it patches `pageSettings.template` through the same `patchPageSettings` seam `kind` uses (`{ ...(entry.pageSettings ?? PAGE_SETTINGS_FALLBACK), ...next }`: it spreads the existing settings, so every other key rides along, and a page with none starts from the app's floor, so the new key never has to stand alone). Picking on a page **with words or ink** (ink is content, F6) **opens a new page** and the words never move. Re-picking the page's own template with words is a no-op, as in the mockup.
- **The path:** `applyTemplate(kind)` generalizes `applyScreenplayTemplate`: `flush(); flushNow(); navigate(unbornHref({ origin, binderId, template: kind }), { state: { fromBoardId: id, fromBoardTitle: pageTitle } })`. `UnbornDescriptor` gets a `template` field (URL param, beside `structure`), so the address still describes the door and a reload keeps it (PB1). **No row is born until the first word** (PB1 holds: unlike Screenplay, a template here does not change the kind of document, so it is not a "durable commitment" birth); at birth `pageSettings.template` is written with the first word, through `patchPageSettings`.
- **The Back note is the existing return chip, not a new widget.** PW1's chip already says "Back to <title>" and, by the page-primacy canon, returns the writer to the exact writing state (scroll, caret, mode). The mockup's "Opened as a new page   Back" is that chip with a different caption. Plan: when `location.state` came from a template pick, the chip reads "Opened as a new page · Back"; it lives in the same fixed track, so the page rect never moves (self-check below). Whether it dismisses on the first keystroke (the mockup) or persists (the chip today) is Q3.
- **Page is primary, self-check.** (1) The picker lives in the drawer's fixed track, so the page rect is identical open or closed (asserted, as the existing drawer checks do). (2) In place: the editor does not unmount, only its lens changes. New page: that is the one lawful departure ("opening different work"), with a one-tap stateful return. (3) The chip is that return.

## 3. What happens to the existing Screenplay
- **Storage and editor are untouched:** `pageType: 'script'`, `script` jsonb, `ScriptEditor`, the `structure=screenplay` door that item 104 depends on (`requestScreenplay` still births at zero words by the ruled PB1 amendment).
- It becomes **one row of the picker** (sketch + word: "Screenplay" in Arbor, "Script" in Flux), drawn brass when the page IS a script page (the `selected` flag that exists today).
- **No conversion in either direction.** A screenplay page with words picking Outline opens a new page; an Outline page with words picking Screenplay opens a new page. The one open edge is an **empty** screenplay page (a freshly chosen Screenplay is exactly that) picking another template: converting in place means un-scripting a page (`pageType`, `script` cleared). Lean: open a new page there too, so a page never changes species; see Q2.
- `ScriptEditor` already passes `templates: [{ key: 'screenplay', selected: true, onApply: () => {} }]` ("pressing a choice already made changes nothing"), so the picker already shows Script as the current choice on a screenplay page, as the mockup expects; it is extended to the full row set, with the other rows opening a new page.

## 7. Hand-ups (each with a lean)
- **Q1: Title Page as a lens or as a small form.** The mockup draws five separately editable fields on an absolutely positioned sheet; the ordinary editor flows text in rows and cannot put a word line on the same row as the first contact line. Lean: a **small structured editor over the canonical text** (five fields, parse and serialize), which is the ScriptEditor pattern at one-tenth the size. Rival, in its strongest form: pure lens (decorations only, no second editor) keeps one typing path and one caret model but cannot reproduce the right-hand word line without a float hack on the typing path, which carries the unmeasured risk. Outline and Bibliography are lenses either way.
- **Q2: an empty Screenplay page picking another template**: new page (lean, a page never changes species) or convert in place (no orphan empty page).
- **Q3: the Back note**: the mockup's note disappears on the first keystroke; the return chip persists. Lean: keep the chip's persistence (canon: every departure offers a stateful return) with the new caption.
- **Q4: numbers in exports.** Lean yes (the file should match the page the writer sees, and it is the only way levels survive `.txt`). Rival: export the raw tabs and leave levels to the reader, which breaks `.md`.
- **Q5: Custom.** Dropped with the mockup. Say if it should stay as a placeholder.
- **Q6: Bibliography extras** (sorting A to Z, a "Sources" count) are not in the mockup and not planned.
- **Q7: Title Page word line** is typed free text as in the mockup; an auto-fill from the live count is a later add.
